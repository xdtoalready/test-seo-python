## 2. Способ активации ПО

ПО не использует традиционные лицензионные ключи. Активация и работа ПО осуществляется в двух режимах:

### 2.1. DEMO режим (для экспертной проверки)
- Не требует регистрации или активации
- Использует предзаписанные mock-данные для демонстрации функционала
- Активируется автоматически при запуске с переменной окружения `ENVIRONMENT=demo`
- Не требует подключения к внешним API сервисам

### 2.2. PRODUCTION режим (для рабочей эксплуатации)
- Требует регистрации пользователем собственных API ключей в следующих внешних сервисах:
  * SerpAPI (https://serpapi.com) - для получения результатов поиска
  * OpenRouter (https://openrouter.ai) - для ИИ-анализа текстов
- API ключи предоставляются непосредственно владельцами этих сервисов
- Правообладатель ПО не контролирует и не управляет этими ключами
- Пользователь самостоятельно создает аккаунты, оплачивает услуги и получает ключи доступа

### 2.3. Технические особенности интеграции

ПО использует внешние API сервисы для получения данных и ИИ-анализа.

**Текущая реализация:**
- **SerpAPI** - для получения результатов поиска (Яндекс, Google)
- **OpenRouter** (DeepSeek V3.2) - для ИИ-анализа текстов

**Возможность замены источников данных:**

ПО разработано с открытым исходным кодом, что позволяет при необходимости 
модифицировать интеграции с внешними API. Основные точки интеграции 
локализованы в отдельных модулях:
- `services/serp_service.py` - получение результатов поиска
- `services/llm_service.py` - ИИ-анализ текстов

При необходимости перехода на альтернативные источники данных (например, 
российские API) требуется модификация указанных модулей с сохранением 
существующих интерфейсов (входные параметры и формат возвращаемых данных).

**Важно для независимости от внешних API:**
- ПО включает **DEMO режим**, работающий полностью автономно без внешних API
- Исходный код открыт и может быть модифицирован под любые требования
- Архитектура построена на стандартных Python библиотеках (FastAPI, httpx)
- Для интеграции с российскими LLM (GigaChat, YandexGPT) потребуется:
  1. Модификация llm_service.py (~200-300 строк кода)
  2. Адаптация промпта под особенности модели
  3. Обновление обработки ответов
- Для интеграции с Yandex XML API потребуется:
  1. Модификация serp_service.py (~150-200 строк кода)
  2. Изменение формата запросов
  3. Парсинг XML вместо JSON

**Оценка трудозатрат на переход:**
- Замена SERP провайдера: 4-8 часов разработки
- Замена LLM провайдера: 8-16 часов разработки
- Полная замена обоих: 1-2 рабочих дня

## 3. Технические средства активации ПО

### 3.1. Для DEMO режима
Технические средства не требуются. Активация происходит автоматически при запуске Docker контейнера с параметром `ENVIRONMENT=demo`.

### 3.2. Для PRODUCTION режима
Пользователь предоставляет свои API ключи через:
- Конфигурационный файл `.env`
- Переменные окружения Docker контейнера

Проверка корректности API ключей осуществляется функционалом ПО при первом обращении к внешним API. Для работы требуется доступ к сети Интернет.

---

## 4. Технические средства выпуска и распространения ПО

### 4.1. Формат распространения
ПО распространяется в виде Docker образа (OCI-совместимый контейнер).

**Параметры образа:**
- Имя: `seo-entity-analyzer`
- Версия: тегируется по стандарту Semantic Versioning (например, 1.0.0)
- Размер: ~500 MB (сжатый)
- Архитектура: linux/amd64, linux/arm64

### 4.2. Методы распространения
1. **Docker Registry** (основной метод)
   - Размещение на Docker Hub или частном registry
   - Загрузка через команду `docker pull`
   
2. **Архив образа** (альтернативный метод)
   - Экспорт образа через `docker save`
   - Формат: .tar.gz
   - Передача через файлообменники или на физических носителях

## 5. Управление API ключами внешних сервисов

Правообладатель ПО **не осуществляет** управление API ключами внешних сервисов (SerpAPI, OpenRouter). 

Пользователь самостоятельно:
1. Регистрируется на сайтах сервисов
2. Получает API ключи
3. Указывает их в конфигурации ПО
4. Управляет квотами и оплатой напрямую с владельцами сервисов

В DEMO режиме API ключи не требуются.

---

ПО спроектировано по модульному принципу. Сторонние API (SerpAPI, OpenRouter) являются подключаемыми модулями. Правообладатель обеспечивает возможность замены данных модулей на аналогичные российские сервисы или использования ПО в автономном режиме (DEMO) без обращения к зарубежным серверам.
