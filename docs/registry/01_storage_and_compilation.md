## 1. Технические средства хранения исходного текста

### 1.1. Система контроля версий

**Используемая система:** Git 2.x

**Описание:**
- Git - распределенная система контроля версий, обеспечивающая полную историю изменений исходного кода
- Каждое изменение фиксируется с указанием автора, даты и описания изменений
- Обеспечивается возможность отката к любой предыдущей версии

**Основной репозиторий (на территории РФ):**
- Тип: Git repository
- Размещение: Виртуальные машины в центрах обработки данных ООО «Яндекс.Облако»
- Адреса ЦОД:
  * г. Владимир, мкр. Энергетик, ул. Поисковая 1 к. 2
  * г. Сасово, ул. Пушкина 21
  * г. Калуга, 1-й Автомобильный пр-д 8
- Доступ: контролируемый (SSH-ключи, токены)

**Зеркало репозитория:**
- Резервная копия размещается на GitHub (https://github.com) для публичного доступа и совместной разработки
- Используется для открытых issue, pull requests и документации
- Синхронизация с основным репозиторием осуществляется автоматически

**Важно:** Основная разработка, CI/CD процессы и хранение production-версий осуществляются исключительно на инфраструктуре, расположенной на территории Российской Федерации.

### 1.2. Структура хранения исходного кода

```

├── api/                  # REST API endpoints
```

### 1.3. Резервное копирование

**Метод:**
- Автоматическое резервное копирование через Git (распределенная природа)
- Каждый клон репозитория является полной резервной копией
- Дополнительное резервное копирование на сервере хостинга

**Частота:**
- Непрерывно (при каждом commit и push)
- Полная история изменений доступна в любой момент

## 2. Технические средства хранения объектного кода

### 2.1. Docker Registry

**Используемая система:** Docker Registry / Docker Hub

**Описание:**
- Docker Registry - хранилище контейнерных образов
- Обеспечивает версионирование объектного кода через теги
- Поддерживает контроль целостности через SHA256 хеши

**Хранение образов:**
```
Образ: seo-entity-analyzer:1.0.0
Формат: Docker Image (OCI-совместимый)
Размер: ~500 MB (сжатый)
Архитектура: linux/amd64, linux/arm64
```

### 2.2. Структура Docker образа

**Слои образа:**
1. Базовый образ: `python:3.11-slim` (официальный образ Python)
2. Системные зависимости: gcc, g++ (для компиляции расширений)
3. Python зависимости: установленные через pip
4. Исходный код приложения
5. Конфигурационные файлы
6. Mock данные для демонстрационного режима

**Контроль целостности:**
- Каждый слой имеет уникальный SHA256 хеш
- Docker автоматически проверяет целостность при загрузке
- Образы подписываются для обеспечения подлинности

## 3. Технические средства компиляции исходного текста в объектный код

### 3.1. Процесс сборки

**Инструмент сборки:** Docker Engine 20.10+

**Этапы компиляции:**

1. **Подготовка окружения**
   - Загрузка базового образа Python 3.11
   - Установка системных зависимостей (gcc, g++)

2. **Установка Python зависимостей**
   - Чтение файла `requirements.txt`
   - Компиляция нативных расширений (если есть)
   - Установка через pip

3. **Копирование исходного кода**
   - Копирование всех файлов приложения в образ
   - Создание необходимых директорий (logs, reports)

4. **Конфигурация запуска**
   - Установка команды запуска (CMD)
   - Экспорт порта 8000

**Команда сборки:**
```bash
docker build -t seo-entity-analyzer:1.0.0 .
```

### 3.2. Используемые компиляторы и интерпретаторы

| Компонент | Версия | Назначение |
|-----------|--------|------------|
| Python | 3.11.x | Основной интерпретатор |
| GCC | 12.x | Компиляция C-расширений Python |
| G++ | 12.x | Компиляция C++ расширений |
| pip | 23.x | Менеджер пакетов Python |

### 3.3. Зависимости

**Основные библиотеки (requirements.txt):**
```
fastapi==0.115.5
uvicorn[standard]==0.32.1
httpx==0.28.0
trafilatura==2.0.0
openai==1.57.2
openpyxl==3.1.5
pydantic==2.10.3
pydantic-settings==2.6.1
loguru==0.7.2
tenacity==9.0.0
python-dotenv==1.0.1
```

**Процесс компиляции зависимостей:**
- pip автоматически скачивает и устанавливает пакеты
- Если пакет содержит C/C++ код, он компилируется GCC/G++
- Скомпилированные файлы (.so, .pyd) сохраняются в site-packages

### 3.4. Автоматизация сборки

**CI/CD конфигурация (.gitlab-ci.yml):**
```yaml
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - docker build -t seo-entity-analyzer:$CI_COMMIT_TAG .
    - docker tag seo-entity-analyzer:$CI_COMMIT_TAG seo-entity-analyzer:latest
```

**Процесс:**
1. При каждом коммите запускается автоматическая сборка
2. Выполняются тесты
3. При создании тега версии создается релизный образ
